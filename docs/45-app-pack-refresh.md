## 更新范围

| 应用 | 本轮更新 |
|---|---|
| 浏览器 | 链接按 Hyperlink 候选选择并绑定快照；正文不固定 Document#2；地址栏及搜索提交绑定具体输入目标 |
| 计算器 | 更新桌面根竞态的已知根因，保留元素级瞬态问题；说明窗口观察失败不能作为启动依据，保留 Name 结果通道 |
| 网易云 | 搜索、队列 ref 与各自快照成对；Enter 检查搜索框焦点；未知读取不能推断播放状态 |
| Excel | 名称框提交与单元格粘贴/提交区分目标；调用方须现场识别实际单元格输入面，保持磁盘和公式结果核验 |
| 夸克 | 保留已有搜索绑定；菜单 ref 绑定菜单观察，右键前重新观察；非快照绑定路径使用唯一语义选择器 |
| 腾讯会议 | 日期框全选、粘贴、Tab 增加具体目标；取消按钮绑定确认框快照；不以 HWND 消失单独证明会议结束 |
| VS Code | 命令面板、替换面板、编辑器 ref 全部绑定来源快照；替换值读回、输入提交核验焦点 |
| 微信 | 补齐 ref 绑定和朋友圈空目标；输入焦点、搜索词、文件路径与发送结果核验；修正不支持的 right-click --physical 与特殊字符标量语法 |
| Word | 正文选择、粘贴及加粗断言 Document 焦点；明确文档身份与保存核验 |
| Zotero | 同步场景脚本的快照绑定与目标焦点要求；第二次搜索观察使用 fresh 变量，导出路径读回 |

`click --physical` 仍显式保留。`right-click` 本身是物理操作，但当前 CLI 不接收 `--physical`；移除的是无效参数，未改变执行通道。
截图、双击、右键等不支持快照绑定的路径须使用当场核对的语义目标，不能把旧 ref 当作持久标识。
微信文件发送路线改用文件名 ComboBox 内的 Edit 语义选择器；复合 find 返回稳定目标，不能假定它生成 ref/snapshot。

## 状态与契约

- 原先 verified、且本轮修改实际步骤的路线降为 manual，供逐步观察复验；原 unverified 不提升。
- 未改动的路线保留历史状态，所有 verified_date 保留原真机日期。旧证据不覆盖，也不以本轮静态检查刷新日期。
- ref 占位符统一为完整 `@eN`，与生成它的同次 snapshot_id 配对；不同字段使用不同前缀，调用方负责填值与消歧。
- `apps/` 是应用知识，不是可直接运行的持久化 flow。读取返回成功后仍须比较业务结果；参数预检无法证明焦点或定位在真机有效。
- 通用规范同步到 `skills/actl/PACKS.md`。业务流程 `release-review-draft.yml` 不属于此次应用档案更新，写段仍待联测。
