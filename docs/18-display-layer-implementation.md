# 18 · 紧凑状态条、动作预告与执行反馈

日期：2026-09-27。实现范围：actl 自身调用及已解析动作；不推测上层 agent 的计划和思考状态。

## 1. 显示约定

- 原生单行状态条，280×34 DIP，文字 16 DIP；目标过长截断，控制区域固定。支持非整数 DPI 和跨屏调整。
- 左侧统一状态圆点；右侧方框用于停止操作，不依赖 emoji 字体。托盘使用圆角框与状态点，按原生尺寸采样。
- 中部：目标摘要与短动作。键盘、鼠标、剪贴板由执行端的组合影响字段驱动，不按命令名猜。
- 右侧方框始终是“请求停止”，不会第二次点击就恢复。清除停止必须在右键菜单显式选择。
- 完成只称“调用完成”。部分送达、失败、请求停止、确认本次停止、状态未知各自独立。
- 详情由左侧点击或右键菜单打开；目标、状态、相对耗时及必要影响/错误保留，省略空字段与实现类型。
  详情与菜单使用同一深色圆角面板和 16 DIP 文字，内边距 12 DIP；菜单宽 136 DIP，详情宽 280 DIP。
  点击外部或 Esc 关闭，菜单支持上下键与 Enter；详情不是阻塞消息框，不暂停显示心跳。
- 中部可拖动，开始拖动即请求停止。拖动不等于已确认停止，也不承诺撤销在途调用。
- 保留 Ctrl+Alt+F12；注册失败仍可点右侧方框。空闲没有呼吸动画或持续重绘。

## 2. 事实来源

`actl-core::signal_session` 为每次 CLI 调用创建身份，以标准线程每秒写一次心跳；结束时先停止心跳线程，再发布终态。不引入 async 或新直接依赖。

状态快照写入 `calls/<call_id>.json`，每个调用独占一个文件；同时 best-effort 更新原有 `state.json`，供旧消费者读取。独立调用互不覆盖事实，临时文件也按调用区分。所有显示写入失败均不影响 stdout envelope。

动作由真实执行位置发布，携带动作序号、阶段、输入影响、已解析目标、时间及有效期。位置使用虚拟桌面的物理像素。影响只描述设备和焦点，不记录键值、输入正文或剪贴板正文。

每个调用保留最近 32 个终结动作，消费者按调用身份及序号去重；启动前的记录和超过 2 秒的记录不补播。终态调用文件按时间和数量清理（60 秒、最多 128 个近期终态）；发布端和显示端均触发清理。运行中调用有心跳续期。

主显示优先呈现运行调用，并合并同时运行调用的输入影响。详情提供运行调用数量。它不是跨 agent 的调度器，也不会把“未注入键鼠”翻译成“可以放心操作”。

## 3. 下一动作预告

只预告已解析的当前待执行动作。副作用动作先确保匹配显示端就绪（缺失时自动启动同目录程序），
等待本次 call_id/action_id 的绘制确认后提供约 300ms 可取消准备间隔，每 25ms 检查停止及显示存活。
启动等待上限 4s、绘制确认等待上限 3s；缺失/隐藏/不兼容/未确认均拒绝执行，不清除停止标志。
读取类命令仍可独立运行，截图短暂隐藏通过 capture 租约表示。完整协议和桌面整理命令见 docs/06 增补。

准备后重新核对目标边界、命中窗口或物理键盘焦点，再执行。等待输入锁之后也检查停止标志；键盘注入前再次核对物理焦点。目标变化拒绝执行，准备标记撤销。

这是一段视觉预告，不是用户授权，也不能保证用户有足够反应时间。需要等待用户确认的任务应由上层显式暂停。上层尚未上报的“下一步计划”不显示。

键盘操作的窗口聚焦也是单独上报的动作；不把聚焦前的准备文案冒充实际输入。UIA、窗口修改及剪贴板写入也检查停止，已发出的 COM 调用无法靠显示条撤销。

## 4. 空间反馈

- 坐标/物理点击：准备时静态圈，实际送达后单次波纹，约 400ms 淡出。表示输入送达，不表示业务成功。
- UIA 语义调用：可靠控件边界高亮，不伪造鼠标落点。
- 原子拖动：准备标记起点，送达标记终点；不伪造实际不存在的持续拖动轨迹。
- 移动、滚动使用静态标记；失败、取消、部分送达不播放点击波纹。
- 高频动作合并到最新空间动作，不堆满屏幕。遵循系统减少动态效果设置。
- 标记使用独立透明、穿透、非激活窗口。状态条没有循环波纹。

## 5. 截图与窗口排除

显示窗口从一般窗口枚举/目标发现中排除；显式 HWND 指向显示窗口时拒绝自动化。

actl 屏幕截图在复制像素前发送同步隐藏请求，收到确认并完成 DWM flush 后才截取；失败返回 `NOT_ACTIONABLE` 或 `INTERNAL`，不静默带入标记。完成后按捕获进程释放隐藏占用；多个截图进程可重叠，进程死亡时显示端回收占用。原本隐藏的状态条不会因截图结束而弹出。

状态条允许普通屏幕共享展示；actl 自己的截图仍走隐藏确认。标记窗口额外请求系统捕获排除，但该 API 不是任意第三方捕获路径的保证。

## 6. 验证与限制

外观细化：保持 280×34 DIP；外框圆角半径 10 DIP，配 0.5 DIP 的低对比内边线。
状态条采用 Direct2D 浮点坐标抗锯齿、DirectWrite 灰度文字，在 WIC 的预乘 BGRA 位图上绘制，
通过 UpdateLayeredWindow 合成。面板内部完全不透明，仅圆角边缘保留透明过渡，
取消整体透明度和窗口区域硬裁切。文字随 DPI 原生重绘，无影响图标时扩展可用文字宽度。
自动渲染测试覆盖 100%、125%、150%、200% 的透明角、实色内部、半透明边缘和预乘像素约束。
动作标记窗口仍沿用原有绘制路径，本轮渲染升级范围为状态条。
停止按钮使用独立的 6 DIP 圆角底面与悬停反馈，移除竖向分隔线；内部方形图标使用较小圆角，
左侧统一使用状态圆点，右侧方框专用于停止操作。停止请求使用柔和琥珀色，失败使用珊瑚红。
已请求或确认停止时按钮变淡，重复点击不重写停止时间；悬停时文字区临时显示
“请求停止 / 已请求停止 / 已停止”，移开恢复当前状态。文字与停止热区位置不变。

可重复的系统应用实测脚本：`fixtures/signal-display.ps1 -CalculatorHwnd <一次性计算器窗口句柄>`，
需要先启动同一构建的 actl-signal；脚本包含显式物理点击，结束时优雅关闭指定的计算器。
不要传入正在使用的窗口。截图前后对照另外按本节记录手动验证。

自动测试采用独立状态目录，不读取或清除用户桌面的停止标志。

自动测试覆盖：v2 golden、旧状态读取、长调用心跳、并发写入隔离、短动作不漏读、去重/过期、不补播、取消/部分送达、终态不失联、停止请求不冒充确认、输入锁探测释放、非整数 DPI。

本机系统应用实测（Windows，200% 主屏，同一轮）：

- 状态条为 560×68 物理像素，对应 280×34 DIP。
- 新开的计算器：UIA 点击、物理点击、按键执行成功；物理点击记录真实落点及 pointer 影响。
- 准备期间请求停止：命令返回 `ABORTED`，动作记录 `cancelled`。
- 坐标点击预告期间还原/移动计算器窗口：返回 `NOT_ACTIONABLE`，不执行旧坐标点击。
- 状态条区域截图：普通屏幕捕获包含状态条，actl screenshot 排除它；捕获后恢复。
- `list-windows` 不返回显示窗口。

实测脚本 `fixtures/display-readiness.ps1` 使用独立状态目录和新计算器：自动启动与预告确认、隐藏拒绝、
指定窗口整理/恢复、已改变窗口跳过、停止标志保留均通过。不最小化用户的整个桌面，不注入物理键鼠。
另发现 Windows 锁屏仍可能报告窗口 visible=true；显示就绪增加中心点命中检查。弹层渲染预览可通过
`cargo test -p actl-uia --bin actl-signal export_native_previews -- --ignored` 导出原生渲染像素，
用于锁屏时检查排版；预览不是桌面合成截图。锁屏期间不执行桌面动作。

仍需额外实机矩阵：不同 DPI 的屏幕之间迁移、辅助技术、远程桌面、安全桌面、全屏独占游戏。
自绘弹层已支持键盘导航，辅助技术语义仍需专项验证。详情不是完整任务面板；不提供跨调用任务暂停/恢复、
外部模型计划或业务结果自动验证。key-down 的调用结束不等于按键已释放，需要配对 key-up。

## 屏幕边缘状态提示（2026-09-27）

显示端增加四边圆角细线与内侧柔光，中央不创建覆盖窗口。每屏仅四条 32 DIP 窄窗口，
使用预乘 Alpha；边线约 1–2 DIP，圆角 18 DIP。蓝色运行态约 3.6 秒一个低幅呼吸周期；
检查点、前置条件失败、待核对及停止等待使用静态琥珀色；用户暂停使用静态灰蓝线。
完成、停止确认、无活动和状态失联后 600ms 淡出；系统关闭客户区动画时，运行态静止、结束立即隐藏。
颜色只辅助顶部状态文字，不代表操作成功或暂停已确认。

有动作几何时选择目标矩形、起点和终点涉及的显示器，支持负坐标及跨屏目标；
只读等待和检查点没有几何时使用状态条所在屏幕。按各屏 DPI 绘制并随屏幕配置变化重建。
位置/配色未改变时复用像素，只更新透明度；截图握手同步销毁边缘窗口，恢复后按最新状态重建。
显示隐藏、退出时一起清理。窗口设置 layered/transparent/noactivate/toolwindow，
命中测试返回 HTTRANSPARENT，并加入自动化目标排除；不新增输入能力和物理输入行为。

验收入口：普通 gate 覆盖状态配色、渐隐、减少动态、负坐标交集、四条无重叠几何及预乘像素。

短暂显示三种原生边缘，核对焦点不变、命中穿透、排除自动化目标及销毁。
实体多显示器迁移与长期 GPU/电量观测仍需对应硬件环境验收。

本轮验证：cargo xtask gate 通过，136 项测试通过、2 项人工测试默认忽略。
另单独运行原生边缘交互测试通过，验证三种配色窗口的焦点、命中穿透和目标排除。

## 交互修整（2026-09-27）

- 状态圆点直径从 6 增至 12 DIP，中心和文字起点不变；边缘线的距离场宽度累计增至原来的 4 倍，轮廓内缩 4 DIP，避免裁切。柔光范围与透明度不变。
- 原生菜单子按钮转发鼠标悬停状态，焦点和点击继续保留原生可访问性。弹层缓存最多 12 份、8 MiB 栅格；状态条只因可见内容变化重绘，调用快照由后台线程读取。
- 流程控制窗口打开时固定 run_id，并显示该标识；无调用快照时仅自动选择唯一未完成流程，有多个候选时不猜测。关闭重开可重新选择；已打开窗口不会被另一命令静默改绑。
- 暂停和继续经后台线程调用配套 CLI，读取退出码与 JSON 结果；相同窗口进程内的重复请求合并。暂停请求已写入不等于已暂停，以持久状态为准；跨进程并发仍由执行器文件锁裁决。
- 详情合并到可聚焦的流程控制窗口，16 DIP 字号，可选择、复制和滚动，每 500ms 更新；文本不变不刷新，变化时保留选区与滚动位置。失败信息保留到下一次操作，后续操作清除旧错误。
- 同一流程暂停或等待时保留最近动作的目标几何；新流程不继承，显示器移除时回退到状态条所在屏幕。
- 拖动状态条仍请求停止，文字明确说明原因；不会自动清除用户的停止标志。关闭控制窗口也不等于停止已启动的流程。
