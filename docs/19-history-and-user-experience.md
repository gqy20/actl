# 操作记录、任务归档与日常体验

日期：2026-09-27。本文区分本轮落地与后续设计；协议以 docs/06 为准。

后续更新：用户授权的 YAML 流程层现已实现命令边界暂停、恢复与结果核对，见
[20](20-yaml-workflow-protocol.md)。下文“后续”描述保留原讨论背景；完整桌面接管仍未实现。

## 1. 管理目标

用户能知道程序做过什么、哪些结果经过验证、遇到问题如何继续；日常运行尽量不打断工作。
actl 保持原子操作 CLI 定位。智能体负责跨调用任务编排、成果判断和反馈整理。

## 2. 本轮落地

| 内容 | 实现与边界 |
|---|---|
| 操作历史 | `%LOCALAPPDATA%/actl/history/<call_id>.jsonl`，按调用独立追加，记录调用开始/结束、batch 步骤和动作阶段；不记录心跳 |
| 任务关联 | 调用方设置 `ACTL_TASK_ID`；没有任务 ID 时仍保留调用历史 |
| 查询 | `history --task <id> --limit 20`，返回最近调用事件；未结束的记录标记不完整，不能直接判为失败 |
| 任务归档 | `task-archive --file report.json`，保存有版本的不可覆盖报告；程序明确标注 caller 来源 |
| 内容最小化 | 自动日志不保存命令参数、窗口标题、正文、剪贴板、截图、错误消息原文；保存动作类型、影响和错误码 |
| 保留 | 操作记录 7 天/64 MiB，任务报告 30 天/32 MiB，单调用 1 MiB，报告输入 64 KiB；写入时机会式清理 |
| 记录失败 | stderr 输出 INTERNAL 诊断，操作本身不因日志失败被重试；显式归档失败返回错误 envelope |
| 显示文案 | 等待说明为“等待条件满足”；错误详情保留代码并补一个简短建议，不根据错误码猜测具体故障原因 |
| 收尾规则 | skill 要求保留成果窗口和用户原有窗口，仅清理无用临时窗口；明确部分完成与验证结果 |

最近一小时写入的文件和有新鲜 Running 心跳的调用受到清理保护。容量是清理阈值，
并发写入和当前文件增长可短暂超出阈值；无法释放容量时拒绝新日志/报告并报告错误。
没有常驻清理器：长时间不运行 CLI 时，过期文件不会自行消失。恢复窗口的 desktop 记录
不在清理目录中。诊断 trace 仍按需输出 stderr，由调用方决定是否保存。

日志不等同于防篡改审计，也不保证断电时最后一条事件持久化。崩溃留下的无终态记录
只表示结果未知。报告中的 verification、verified 均是提交者陈述，actl 不自动背书。
报告可以包含敏感信息，提交者应主动简化；evidence 仅保存引用，不复制文件，链接可能失效。

## 3. 任务收尾与反馈

1. 调用方生成任务 ID，在自己的子进程环境中传递，不修改用户全局环境。
2. 执行和验证分别记录。Delivered 只表示动作已送达，调用 Done 不等于任务成功。
3. 根据回读/结果文件判断 completed、partial、stopped 或 failed，写出未完成项。
4. 查询 call_id，提交简短归档。用户反馈与智能体建议分别标明 source，未复现猜测设为 verified=false。
5. 复现后才把经验更新到应用 pack；通用流程进入 skill，缺陷进入代码和回归测试。

成果文档、报表、结果页面默认留在桌面；临时窗口才清理。恢复窗口布局必须重新核对实例与状态，
不覆盖用户期间的新布局。剪贴板完整恢复、原焦点恢复未实现，不作自动承诺。

## 4. 后续体验设计与验收

### 控制权交接

拟议流程：请求接管 → 阻止新动作 → 等待在途动作结束并释放输入 → 确认交接 → 人工处理 →
用户允许继续 → 重新观察与定位。需要任务协调器及确认协议，本轮没有新增暂停/继续按钮。
现有停止标志继续保持粘性，不因等待时间到期而清除。

验收：焦点变化后不自动抢回；部分输入报告真实送达情况；未收到执行端确认不显示“可以操作”；
恢复时旧坐标和旧元素引用必须重新验证。轻微鼠标移动不能导致频繁误暂停。

### 稳定节奏与等待

未来任务阶段由调用方报告，状态条可保持“填写表单”等稳定摘要；底层动作身份与显示确认独立。
不能通过防抖隐藏需要确认的动作预告，也不能把调用间隙推断为智能体思考。
现有波纹已经合并同轮到达的动作，减少动态效果设置继续生效。演示速度配置尚未实现。

验收：短动作可感知，连续动作不满屏闪烁；无已知总量时不显示百分比；等待原因来自实际执行状态。

### 人工介入与恢复

登录、验证码、结果不明确等情况由上层提出一个具体请求。自动重试只适用于重新观察等已知安全步骤；
提交、发送、写入结果不明确时先验证。未来介入卡需要目标定位、交接确认与返回任务的明确入口。

### 日常显示与无障碍

保留 16 DIP 字号、稳定位置、非激活提示和键盘操作。后续专门验证 100/150/200% DPI、跨屏移动、
高对比度、屏幕阅读器；当前自绘内容不能据此宣称已满足屏幕阅读器可访问性。
常规步骤不发系统通知，仅在需要介入或重要结果时提醒。通知偏好与首次使用教学尚未新增。

### 独立运行环境

单独评估应用实例、登录态、文件、剪贴板与物理输入隔离。不把最小化、第二显示器或普通 Windows
多桌面视为隔离。该能力超出本轮范围，必须重新评审 PRD 与执行架构后再实现。
