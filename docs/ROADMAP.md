### 执行顺序

1. 先验证已有交接、急停、目标身份和恢复，再逐项复验应用 YAML。
2. 交付独立目标预览：仅显示目标边框与业务动作说明，可取消并自动退出；不执行目标动作、不授予桌面权限。技术诊断供 agent/开发者使用，普通用户看到应用、目标和意图。
3. 根据失败证据补局部观察、候选诊断与档案参数检查，减少重复扫描和输出；复杂选择器按场景增补。
4. 完成固定环境性能、金任务和非开发机验收；浏览器正式接入、录制修复、探索与 MCP 在后续按需求推进。

- [ ] 预览剩余验收：真实鼠标关闭、真实应用 provider 的控件重建、显示端急停联测、多屏 DPI、复杂遮挡与并发预览；自有原生目标的失效/退出回归记录见 [目标预览](46-target-preview.md)，不能外推到尚未覆盖的应用。
- [ ] 候选纠正剩余验收：实际鼠标切换/选择（computer-use 两轮受阻）、真实应用同名候选、provider 重建、多屏 DPI 与遮挡变化；同一快照的显式候选切换实现及本机证据见 [46](46-target-preview.md)。自动收集歧义候选仍待后续实现；选择结果必须重新核验后执行。

- [ ] 继续验收 ZCode 虚拟化、provider 重建及观察瞬态失败，见 [50](50-deep-container-query.md)；保留首轮 STALE_REF 记录。全窗口基线截断时只报告局部可用性，不计算削减率。

设计及逐批验收见 [目标预览](46-target-preview.md)。以上预览交付不替代本节既有可靠性和发布门槛。

### MCP · 本设备启动服务，其他设备调用

计划拓扑：

```text
其他设备上的 MCP 客户端 / agent
              ↓ 经授权的网络连接
被控 Windows 设备上显式启动的 MCP 服务
              ↓ 复用 actl 的命令与安全护栏
         本设备上的 Windows 应用
```

服务运行在要被操作的设备上，向其他设备提供本设备的操作能力。本机 CLI 仍可独立使用。
MCP 适配独立于核心；这是待设计能力，当前没有可用的 MCP 启动命令或远程接口。

实施前需完成：

- [ ] 选择适合跨设备访问的 MCP 传输方式，定义监听地址、身份认证、加密与访问授权；
  不将本地 stdio 接口误当成可直接远程访问的服务。
- [ ] 定义客户端与本地任务的关联、并发排队、断线后的暂停/结果查询以及授权撤销；
  写入结果不确定时禁止因网络重连自动重放。
- [ ] 复用本机交接提示、暂停/继续、急停、焦点校验与操作记录，远程调用须在本机可见且可中止。
- [ ] 完成双设备验收：授权调用、拒绝未授权请求、人工接管、网络中断与恢复核对。

MCP 的目标是跨设备访问；本地 `serve` 的目标是观察与执行性能，两者独立评估。
远端客户端可以来自不同系统，这不意味着要实现 Linux/macOS 的桌面执行后端。
