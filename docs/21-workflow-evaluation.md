# YAML 流程 v1 测试与体验评估

日期：2026-09-27。实现提交：38bf625；本轮另补断言预检修正及可复现评估脚本。

## 结论

可以用于步骤明确、有稳定语义选择器和结果断言的顺序任务。暂停、恢复和异常退出已有可验证的
执行语义，适合作为第一版流程基础。复杂任务的结果传递、人工介入说明和快速暂停仍需要补齐。
本结论不等同于真实业务应用的生产验收。

GUI 应用未被关闭；只终止了测试创建的 CLI 进程。用户原有停止标志未修改。

## 发现并修正的问题

`flow-validate` 原先通过 clap 校验后，未继续检查 wait/verify 的运行时断言要求。
无条件 wait 可以预检成功，运行到该步才失败；若前面有写操作，会增加恢复成本。

先新增复现测试确认失败，再补齐：wait/verify 恰好一个断言模式、断言选择器语法和 wait 属性谓词。
同一校验覆盖 run/before/verify；非法流程在建立运行目录前拒绝。预检不检查当前窗口实际存在，
也不能判断用户编写的后置断言是否足以证明业务成功。

## 体验评估

### 已达到的效果

- 暂停请求和暂停确认分开，下一步不会越过暂停边界。
- 恢复能跳过完成步骤，不依赖原 YAML 仍在原位置或保持原内容。
- 错误、停止、中断、需核对结果有不同机器状态，智能体可以据此选择下一步。
- 新运行 ID 与操作历史关联，能追溯执行次数与动作阶段。

### 仍有明显改善空间

以下为首次评估时的问题清单；本轮已实现轮询等待协作暂停和暂停原因显示，详见文末补测。
输出绑定与计划修订仍未实现。

1. **长调用期间暂停不够快**：wait 自身还不会读取流程暂停请求，只在返回后暂停。
   当前实现诚实显示等待确认，但不能承诺即时接管。优先让可协作的 wait 轮询响应暂停；
   不应强杀 COM 调用来缩短表面耗时。
2. **暂停原因不够直观**：运行记录有 reason 和步骤错误码，显示信号仅传递流程标题与状态。
   用户界面需要区分计划检查点、用户请求和执行失败，并给出一条下一步建议。
3. **步骤结果不能传递**：adapter 丢弃命令 data，只有成功/失败进入执行判断。
   查询后按查询结果决定目标的复杂任务仍需智能体在外部观察；后续优先做按需结果查看和受限输出绑定。
4. **计划修改成本较高**：原计划固定提高了恢复可靠性，但修改后必须新建运行。
   后续应引入计划修订和已完成步骤兼容性检查，不能简单沿用旧完成标记。

托盘入口与视觉状态本轮只经过编译和现有模型/绘制测试；没有重启用户当前显示端进行点击验收。
跨 DPI、屏幕阅读器以及真实写入应用的完整体验需要另做真机回归。

使用 computer-use 插件的 `@oai/sky` 启动计算器、观察截图并逐次点击 `2`、`+`、`3`、`=`。
每次点击后重新观察，最终截图确认显示 `5`。以下流程命令由发布版 CLI 执行，窗口输入全部由
Computer Use 完成；这是人工介入后的流程恢复测试，不是 YAML 自动点击或托盘菜单验收。

## 控制协议与可访问入口补测

同日新增 `actl-signal --controls` 后，Computer Use 成功列出“actl · 流程控制”，
读到标准按钮的名称、角色和禁用状态。原悬浮条未替换；控制窗口使用独立 LOCALAPPDATA。

- 实际点击继续，流程进入 60 秒窗口等待；再点击暂停，保存 paused/pause_requested，
  等待步骤 pending、attempts=1、error_code=null，下一步 attempts=0。
- 再次继续后点击停止，保存 stopped/stop_requested；继续按钮禁用。
- 点击“允许后续操作”解除测试目录的停止标志，不自动启动执行器。
- 另一个检查点流程点击继续后 completed，两步 attempts 均为 1。
- 最终控制窗口可直接显示，Tab 从关闭移到停止按钮，Esc 关闭窗口，未触发恢复。
- 原用户停止标志仍保留，测试窗口已优雅关闭。原始运行状态保存在 target/controls-live/。

期间发现控制窗口把停止时间当成未知，导致确认停止后仍显示请求中。先加入失败复现，
再改为与悬浮条共用真实停止时间戳，回归通过。截图和可访问树采集不是同时发生，
发生状态切换后须再次观察，不能用单次采集中的旧树判断按钮仍可用。

新增自动测试以 60 秒 wait 验证 5 秒内响应暂停（宽松回归上限，不是性能承诺）；
before/verify 中断时保留步骤阶段，恢复后写操作不重复。UIA/COM 阻塞仍不可强行打断。
最初 gate 与窗口创建同时执行，两项桌面基线测试失败；停止 UI 操作后顺序重跑通过相关用例。
后续回归还捕获了暂停改动影响验证阶段紧急停止状态的问题；已保留紧急停止的 uncertain 语义，
仅普通暂停保留 verifying，相关状态机测试通过。

该验收覆盖标准控制窗口；自绘托盘菜单、波纹、多屏 DPI 切换和屏幕阅读器仍未完整验收。
