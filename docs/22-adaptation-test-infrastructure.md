# 应用适配测试基建

2026-09-27。本批收束执行入口、产物身份、报告和记事本资源归属。流程状态机继续使用
actl-flow；不增加应用后端、流程语言或依赖。实现入口在 crates/xtask，Makefile 不放逻辑。

## 运行

需要 PowerShell 7（pwsh，复用 PATH）。gate 的执行器离线测试也使用它；Windows CI 已有该运行时。

```powershell
cargo xtask regress --list
cargo xtask regress --suite flow
cargo xtask regress --case golden-task-2
cargo xtask regress --suite system
```

`--list` 只读清单，不构建、不运行应用。其余入口先构建 target/validation/release 下的配套
actl/actl-signal，再把同一个 CLI 绝对路径传给每个用例。不会覆盖或替换正在运行的显示端。
显示端仍受原有配套版本检查约束。

regress-cases.json 是当前接入清单：flow（流程控制评估）、system（系统应用）、scenario
（真实应用手工场景）。ready 仅表示允许调度，不是已通过真机验收。blocked 表示等待迁移，
manual 仅列出、不自动运行。真实应用清单后续逐步登记，不声称已经收录全部探索脚本。

无参数运行所有已登记项；存在 blocked 会返回非零，不能宣称“全量通过”。
指定 suite/case 可单独验证已就绪范围。脚本退出 0=passed、77=blocked，其余=failed；
manual=skipped。只有跳过项、没有任何通过项时也返回非零。失败后不启动后续用例，报告注明 skipped。

## 报告与证据

每轮 target/regress-<GUID>/report.json 保存：

- 执行时间、操作系统、Git HEAD 与工作区是否有改动；
- 二进制绝对路径、版本、SHA-256；
- 每个用例的状态、原因、退出码、耗时、stdout/stderr 文件路径。

每个用例开始前先保存 running，结束后更新报告。若执行器异常退出，残留 running 表示结果未知。
这不是 actl 的持久化恢复记录，不能直接据此重放写操作。日志原始字节分别流式写入两份文件，
避免合并 JSON 与诊断或被管道缓冲区阻塞。PowerShell 用例约定输出 UTF-8。

报告和日志在本地 target 下保留，不自动删除或上传。可能包含窗口标题和测试内容，应作为本地诊断资料。
汇总日志不替代效果断言：成功仍由用例验证，真实应用要另外沉淀 pack 与场景记录。

## 记事本迁移

golden-task-2.sh 仅转发到 golden-task-2.ps1，尊重入口传入的 ACTL。

1. 紧急停止存在或已有 Notepad 进程时返回 blocked；不清除停止、不调用 CLI 清场。
2. 独立 GUID 文件位于本轮目录。支持系统路径和商店版 Notepad 安装路径。
3. 打开测试文件，用唯一标题标记及窗口基线确认新窗口，后续操作绑定 HWND。
4. 写入中英文，读取核验，再 Ctrl+Shift+S 打开另存为。对话框必须是新 HWND、同 PID，
   且 owner_title 包含测试标记；不满足则停止，不退回宽泛的标题选择器。
5. 填入绝对输出路径；最终检查磁盘完整文本（仅规范化 CRLF/LF）。
6. 成功后重新核对 HWND/PID/标题，只关闭测试标签；不关闭整个多标签窗口。
   失败保留窗口供核查，测试文件保留作证据，不丢弃未保存内容。

每次 CLI 调用保存 JSON、stderr、退出码和耗时；30 秒超时只终止本次 CLI，不杀 GUI 或进程树。
超时视为效果未知并停止，不自动重试。清理核对与执行之间仍有竞态，因此真机用例要求空闲桌面。
此用例包含键盘注入和共享剪贴板写入，无物理鼠标操作，不承诺自动恢复剪贴板或焦点。

其他旧 GUI 脚本保留供迁移，但统一入口将有标题清场、固定目录或证据缺口的用例标为 blocked。
不要绕过清单直接批量运行这些脚本。计算器、系统信息、资源管理器已完成下述脚本迁移；
Edge、坐标点击等仍待迁移。

## 第二批：计算器、系统信息、资源管理器

三项 `.sh` 仅转发到对应 `.ps1`，共用 system-fixture.ps1 生命周期和 system-scenarios.ps1
场景实现。每次 CLI 调用记录独立 JSON、stderr、退出码和耗时；30 秒超时仅终止 CLI，
效果未知时保留 GUI，不重放操作。result.json 记录应用版本、窗口身份、清理结果和证据路径。

- 计算器：已有计算器进程则 blocked；通过 AppsFolder 激活商店包，以新 HWND、包内程序路径和进程启动时间确认归属。
  默认重复 3 轮 ref 点击与结果名称验证，RUNS 可设 1–100。要求中文标准模式；宿主窗口和标题栏
  不作为计算器实例，应用窗口归属不唯一时停止，不能视作支持其他版本。
- 系统信息：已有 msinfo32 则 blocked；启动后绑定新 HWND/PID。extract 必须返回至少 30 行、
  每行两列，并包含 Windows 名称和 BIOS 项。tree-flatten 允许已知 Hyper-V 单列提示行，
  其他不完整行仍拒绝。断言针对中文系统摘要页。
- 资源管理器：每轮 GUID 目录包含 60 个垫位文件；要求出现基线外的新 HWND。
  打开后新增目标文件，find 必须报告 item-container，随后 get/verify 核对名称。
  普通可见项查找成功不能代替虚拟化路径验收；目录和文件保留作证据。

清理前重新验证 HWND、PID、进程启动时间、窗口类和标题标记。资源管理器还要求 UIA 树中
只有一个带测试标记的 TabItem；没有足够证据或出现其他标签时保留窗口并报告失败。
身份核对与关闭之间仍有竞态，要求桌面空闲。启动成功但归属未能确认的窗口同样保留供核查。

迁移前离线测试复现了旧脚本按标题清场的问题。新增测试覆盖 HWND/PID 复用、身份变化、
停止与已有进程零 CLI 调用、未知效果不清理，以及资源管理器多标签拒绝关闭和单标签精确关闭。
2026-09-27 首次三项真实入口均被现有紧急停止阻止，报告为 blocked；当时未清除停止标记。
ready 仅表示可调度，不代表不同系统版本均已验收。

用户授权清除停止标记后，后续真机测试发现并修正了三处脚本问题：商店计算器必须激活而非直接
执行包内 exe；系统信息会持有日志管道；其摘要中的 Hyper-V 提示只有一列。CLI 退出后最多
再等待管道 1 秒，然后取消读取并保存已捕获字节；只有完整 JSON envelope 和成功退出码才接受。
`streams_drained=false` 表示未等到 EOF，诊断日志可能不完整。不会为等待 EOF 关闭 GUI。

### 计算器输入方式对照（2026-09-27 23:06，独立环境头）

Windows 10.0.26200.0 中文，计算器 11.2607.0.0；使用现有 validation/release/actl.exe，
SHA-256 为 22375ECD7F317720E397C705964100A45086190DD3B3DFDBE71714D006F021DD。
本组不与此前耗时跨轮比较。算式为 `123*456+789=`，标准模式结果 `显示为 56,877`。

每种方法 3 次；顺序轮换：click/batch/keyboard → batch/keyboard/click → keyboard/click/batch。
各次都先 UIA 清空并 snapshot；逐次点击用 12 次 CLI ref click，batch 将相同 12 条命令放入
一个进程；键盘用 `type id:num1Button '123*456+789=' --app hwnd:<本轮窗口>`。
type 报告 keyboard=injected、pointer=none、clipboard=untouched，无 paste，无物理鼠标点击。
每次均用 get 留存结果，再 verify Name 精确断言。没有调整输入法，未测试其他输入法状态。

| 方法 | 输入耗时，3 次（毫秒） | 输入中位数 | 总耗时中位数 | 正确次数 |
| --- | --- | --- | --- | --- |

输入计时包含 CLI 启动、定位/聚焦、执行和结果读取；总计时另含清空、snapshot、get 和 verify，
