## 扫描结论(三问三答)

### Q2 轮询间隔:50/100/250ms 对 wait 检出延迟无差异

| poll | 中位检出开销(5 样本) |
|---|---|
| 50ms | 5064ms(样本 4504-7915) |
| 100ms | 5359ms(样本 5185-5740) |
| 250ms | 5507ms(样本 5496-5759) |

三组置信区间完全重叠;瓶颈是被等事件本身(记事本启动 ~5s),不是轮询粒度。
**结论:维持 100ms(生态共识值在本地验证无损失)。**

### Q3 分批大小:吞吐随批大小单调小幅改善,停止粒度等比变粗

| segment | 300 字符中位耗时 |
|---|---|
| 16 | 2888ms |
| 32(现默认) | 2981ms |
| 64 | 2745ms |
| 128 | 2480ms(-17%) |

128 比 32 快 ~17%,但停止响应粒度从 32 字符粗化到 128(人按紧急热键后最多多打进 128 字符)。
**结论:维持 32(吞吐差异在噪声边缘,粒度价值更高);若未来出现长文本吞吐需求再议 64。**

### Q5 焦点链:所有配置 10/10,当前值有充分裕量

60ms×3 / 120ms×2 / 120ms×3 / 150ms×3 全部 10/10(n=10,记事本)。
**结论:维持 120ms×3。**降到 60ms×3 的证据不足(n 小、单应用),且 60ms/命令的收益(~4%)在环境噪声内。

## 总结论

**三个默认参数全部维持现状——生态共识 + 本次本地验证均支持现值。** 扫描框架已就位(timing 环境旋钮 + 两 fixtures),今后任何"变慢了"的回归或参数调整提议都可一条命令出数。
