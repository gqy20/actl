# 03 · RPA 与 Quicker 的区别,以及可借鉴什么

日期:2026-09-26

## 1. 核心区别:同一套底层,完全不同的上层

两者的底层技术高度同源——都是"选择器/accessibility 定位 + 键鼠模拟"。差别全在上面三层:

| | RPA(UiPath / 影刀 / Power Automate Desktop) | Quicker |
|---|---|---|
| 自动化的**单位** | **流程**:几十上百步的长事务,跨应用,可跑数小时 | **动作**:秒级小操作,单点提效 |
| **触发** | 计划/队列/事件,**无人值守**(unattended) | 人按出来(中键面板/快捷键),**人在场** |
| **上下文** | 流程自带全部输入,运行时零交互 | 强依赖"此刻"上下文(选中文字、当前窗口) |
| **可靠性哲学** | 一次编排、万次重放,失败无人补救 → 容错是生死线 | 失败人再点一次 → 容错低一个量级 |
| **用户** | 企业 IT / 财务 / 供应链 | 个人知识工作者 |

一句话:**RPA 是流水线机器人(替代人的重复劳动),Quicker 是瑞士军刀(放大人的单次操作)。** 因此 RPA 把工程预算全押在"可靠性工程"上,Quicker 押在"触发与上下文感知"上。

## 2. 对本项目的定位启示

本项目架构上站在两者的**底层交集**上;编排层(流程图 vs 动作面板)由 agent 替代。由于 agent 将**无人值守**地执行多步操作,可靠性哲学必须向 RPA 看齐——**我们做的是"AI 时代 unattended RPA 的手"**。RPA 20 年沉淀的可靠性工程因此是最对口的借鉴库。

## 3. 值得借鉴的五条思路(已落到设计决策)

| # | RPA 思路 | 落到 CLI 的设计 |
|---|---|---|
| 1 | **选择器回退链**(UiPath strict/fuzzy selector + fallback) | snapshot 时为每个 ref 同时生成 primary 定位(UIA 路径)+ fallback(名称模糊匹配/锚点),失效时逐条回退。比 agent-desktop 的"STALE_REF→全部重来"省 token 和轮次 |
| 2 | **操作-验证闭环**(每个动作后验证预期状态) | click 原生支持 `--expect <predicate>`;verify 族命令(元素存在/值/勾选状态/顺序)为一等公民。把可靠性从 agent 的 prompt 技巧下沉为工具原语 |
| 3 | **结构化提取**(scraping:表格→DataTable) | `extract` 命令(表格→JSON 数组),agent 处理老 Win32 应用抠数据的刚需,比逐格点击快百倍 |
| 4 | **等待谓词而非 sleep**(Retry Scope / 等元素出现/等属性变化) | 系统化的 `wait` 谓词语法(等元素/等窗口/等属性/等消失) |
| 5 | **失败留证**(异常自动截图 + 上下文 dump) | 每次错误返回附 evidence(出错时局部元素树 + 可选截图引用),加速 agent 自愈与人工调试 |

参照:微软 [AutoGenesis/pywinauto-mcp-server](https://github.com/microsoft/AutoGenesis) 的 verify_* 工具族即 RPA 思路的 MCP 移植;OpenAdapt 在验证"录制→LLM 编译"路线。

## 4. 不搬的与该警惕的

**不搬**:
- 可视化流程设计器(agent 循环 + 自然语言已替代);
- Orchestrator 集中编排(短期无需求);
- 录制器(后期加分项:录制输出转为 agent 可复现的"操作轨迹")。

**警惕 RPA 的头号教训——"脆弱自动化"**:RPA 维护地狱的根源是 UI 一改选择器全崩且无自愈能力。本项目的差异化恰在于 agent 天然可自愈(UI 变了重新 snapshot 重新规划),因此**错误协议要为自愈设计**:错误返回不只是报错,而是携带"树发生了什么变化"的线索,使 agent 下一轮恢复成本最低。

**哲学分野:RPA 求稳(锁死流程),本项目求韧(快速恢复)。不要把 RPA 的"锁死"做进协议。**

## 5. 对估算的影响

以上借鉴约增加 1,500–3,000 行(fallback 定位、verify/extract 命令、evidence 机制),代码量增幅有限,但显著提高"从演示到可用"的跨越率——RPA 行业 20 年证明 GUI 自动化的成败全在可靠性工程层。
