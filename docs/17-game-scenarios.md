## 1. 定位:大型游戏 = UIA 失明的极端形态

大型游戏(DirectX/Vulkan 自绘)的内容层不在 UIA 树里——与抖音互动层、
微信自绘菜单、Canvas 同一形态,视觉兜底协议(screenshot + VLM + click xy)
就是为此建的。游戏不是新基建,是现有路线的应用扩展;可行性按环节分层:

| 环节 | 可行性 | 依据 |
|---|---|---|
| 启动器/平台层(Steam/WeGame 等 CEF 壳) | 现成 | browser pack "Chromium 同源套用"断言外溢 |
| 慢节奏游戏内操作(挂机/回合制/日常) | 现成 | 视觉循环 1-3s/步,抖音闭环同构 |
| 读屏辅助(人玩 AI 看) | 现成 | screenshot + VLM |
| Minecraft 建造 | 走原生命令通道(§2) | 键盘通道现成,吞吐足够 |
| 实时对抗"代打" | 不可行 | 进程冷启 ~55ms/命令 + 输入保真度不足,架构性(ADR-001) |
| 带内核反作弊的网游 | 不做 | AGENTS 安全红线(不做规避)+ ToS 封号风险 |

## 2. Minecraft 三段式架构(推荐路线)

**第一段·蓝图生成(离线,非 actl)**:目标建筑 → 方块数据 → 贪心合并为
`/fill` 箱体序列。现实地标可从 OSM/DEM/卫星图体素化;这是项目主要工作量,
纯离线脚本问题。

**第二段·命令通道灌入(actl 主场)**:

```
actl press t --app Minecraft            # 开聊天(焦点链自动聚焦游戏窗口)
actl set-clipboard "/fill 120 64 -40 132 70 -28 stone"
actl paste --app Minecraft              # ctrl+v,无元素落点的粘贴原语
actl press enter --app Minecraft        # 落一块
```

注意用 `paste` 而非 `type`——type 需要元素置焦,Minecraft(UIA 失明)给
不出元素;paste 正是为"无元素落点"设计的(v0.1.4)。

吞吐:每条约 3 次进程冷启(~200ms)+ 游戏 tick 处理,保守 2-3 条/秒;
50×50×30 建筑贪心箱体化后约数百到两千条 → 十几分钟灌完,比视觉逐块放置
快三个数量级,且完全绕开瞄准问题。进阶变体:整栋建筑做成 datapack
function 或 structure block,一次粘贴调用。整个循环可包成一个 batch。

**第三段·视觉验收**:

- **F2 原生截图落盘**(.minecraft/screenshots/*.png)——白捡的通道,绕开
  OpenGL 窗口 PrintWindow 可能的黑帧问题,文件直接交 VLM;
- 或 `screenshot --app` / `--rect` 现抓;
- F3 坐标屏 + VLM 核对方位尺寸;偏差用 /fill 修正,循环到满意。

窗口层:窗口标题含 "Minecraft",--app 锚定/focus/xy 守卫正常工作;建议
窗口化或 F11 无边框(勿独占全屏)。

## 3. 缺口登记(M3 候选;"像人一样手工搭"路线才需要)

| 缺口 | 说明 | 量级 |
|---|---|---|
| 相对视角移动原语 | mouse-move dx,dy 增量注入;现有 hover xy: 是屏幕绝对坐标,GLFW 捕获光标下语义对不上。前置 spike:GLFW raw-input 是否吃 SendInput 增量(AHK 的 MC 镜头脚本存在,大概率可行) | PointerSpec 加操作,小改 |
| 鼠标按键 down/up 拆分 | 按住左键挖掘的时长控制;click 现为原子 down+up | 同上 |
| 节奏敏感动作 | 双击空格切飞行的双击时窗等 | Timing 参数试 |

吞吐注:视觉循环手工放置 ~1-3s/块 + 瞄准重试,1000 块 = 小时级;只适合
小作品或"AI 手玩"演示。正经建楼永远走 §2 命令通道。

## 4. 边界(铁律)

- **单机/自有世界/自有服**:完全正当(接近"测试自己参与的游戏"场景);
- **多人服务器**:灌命令是游戏正常功能,但自动化行为看服规;机器节奏
  明显的批量操作会被反作弊插件(Grim/NoCheatPlus 类)盯上;
- **不做规避**:反作弊检测的规避属于 AGENTS 安全红线,永不做;
- **无内存读写**:刻意没有,游戏状态只能走视觉——与 cheat 工具的本质分界。

## 5. 演示显示形态(联动 11 §15)

- **最小化(非关闭)驱动终端**——关闭会杀循环;最小化不影响护栏(前台
  核对/输入锁/遮挡检查照常工作);
- **Minecraft F11(无边框全屏)+ actl-signal 悬浮右上角**——WS_EX_NOACTIVATE
  不抢游戏焦点;Ctrl+Alt+F12 全局逃生,与任何窗口可见性无关;
- 主显示器运行(坐标系统一,视觉循环换算省心;PMv2 后跨 DPI 已正确,
  单屏少一层心智负担);
- 红利:桌面清净 → --rect 截屏只剩游戏内容(VLM 读图更准)、blocked_by
  弹窗闸门/遮挡护栏一路绿灯;
- **前置依赖:失联判定修正(11 §15.3)**——否则 VLM 思考 10s+ 状态条闪
  "失联",演示直接翻车。

## 6. 验收草案(立项时定稿)

1. 一栋小建筑(~10×10×8)端到端落成:蓝图脚本 → actl 灌入 → F2 截图
   VLM 核对通过;
2. 全程状态条无失联误报(依赖 11 §15.3 修正);
3. 灌入吞吐实测入档(命令/秒;timing 纪律:同环境头内比较);
4. 实测后 quirks 入 pack(若值得),unverified 路线禁直接执行。
